# 65816 / 65802 — 16-bit additions vs 6502/65C02

The WDC 65C816 (Apple IIgs; the SNES's Ricoh 5A22 and the SA-1 cartridge chip
are 65C816 cores; the 65802 is the same core in a 6502 pinout) extends the
65C02 to 16-bit registers and a 24-bit (16 MB) address space, while booting in
an **emulation mode** that is binary-compatible with the 6502. Almost every
porting mistake here comes from losing track of *mode* and *register width*.
Track them as you read.

Everything in this file except the last section is CPU-core behavior and holds
on every 65C816 system. SNES-specific differences are in
[SNES / Ricoh 5A22 notes](#snes--ricoh-5a22-notes) at the end.

## Emulation vs native mode — the E flag

- Power-on / RESET puts the CPU in **emulation mode (E=1)**: behaves like a
  65C02, registers effectively 8-bit, stack confined to page 1.
- Software switches to **native mode** with `CLC : XCE` (exchange carry and E).
  `SEC : XCE` returns to emulation. The E flag is "hidden" — you read/set it
  only via XCE through the carry.

## Register width — the M and X flags (native mode only)

In native mode two status bits choose register widths:

- **M flag** (status bit 5): 0 = 16-bit accumulator/memory, 1 = 8-bit.
- **X flag** (status bit 4): 0 = 16-bit X/Y, 1 = 8-bit index registers.

Set/clear them with `SEP #const` (set status bits) and `REP #const` (reset
status bits), e.g. `REP #$30` → 16-bit A and index; `SEP #$20` → 8-bit A.

**Critical for reading code:** the *length of an immediate operand depends on
the current M/X flags.* `LDA #$1234` assembles to 3 bytes when M=0 but
`LDA #$12` to 2 bytes when M=1 — the same mnemonic, different size. A
disassembler (or you) must track M/X to decode the byte stream correctly.
Merlin tracks this with the `MX` directive and `XC` (two `XC`s = 65816); a
wrong `MX` desynchronizes the whole listing.

In emulation mode M and X are forced to 1 (8-bit), and the high byte of the
index registers reads as 0.

## Wider registers and new registers

| Register | Width | Notes |
|----------|-------|-------|
| C = B:A  | 16    | A is the low half; B (hidden) the high half. `XBA` swaps them. |
| X, Y     | 8/16  | per X flag |
| S        | 16    | native-mode stack can be anywhere in bank 0 |
| D (DP)   | 16    | Direct Page register: relocatable "zero page" — direct-page addressing is `D + offset`, not fixed `$00xx` |
| DBR      | 8     | Data Bank register: default bank for absolute data accesses |
| PBR (K)  | 8     | Program Bank register: bank of the PC |

Because of D and DBR, a "zero page" or "absolute" access in 65816 source is not
necessarily at `$00xx`/`$00xxxx` — its physical bank/offset depends on D and
DBR at runtime.

## New instructions

| Instr | Operation |
|-------|-----------|
| REP / SEP #imm | reset / set status bits (used to flip M/X and others) |
| XCE | exchange C and E (enter/leave native mode) |
| MVN / MVP | block move negative/positive (src bank, dst bank operands; C = count-1; uses X,Y) |
| PEA / PEI / PER | push effective address / indirect / PC-relative — for building stack frames & position-independent code |
| PHB PLB / PHD PLD / PHK | push/pull data bank, direct page; push program bank |
| TCD TDC / TCS TSC | transfer C↔D, C↔S (16-bit) |
| TXY TYX | transfer X↔Y |
| XBA | swap the two bytes of C (A↔B) |
| BRL | branch always long (16-bit relative range) |
| JML / JSL / RTL | long (24-bit) jump / call / return — cross-bank |
| JSR (abs,X) | indexed indirect subroutine call |
| COP | software interrupt (coprocessor) via `$00FFE4` (native) / `$00FFF4` (emulation) |
| WDM | reserved / no-op (acts as a 2-byte NOP) |
| STP / WAI | stop clock / wait for interrupt |

## New addressing modes

| Mode | Syntax | Meaning |
|------|--------|---------|
| Stack relative | `LDA d,S` | operand at `S + d` |
| Stack rel indirect indexed | `LDA (d,S),Y` | pointer at `S+d`, then +Y |
| Direct page indirect long | `LDA [d]` | 24-bit pointer at direct page d |
| DP indirect long indexed | `LDA [d],Y` | 24-bit pointer + Y |
| Absolute long | `LDA $123456` | full 24-bit address (ignores DBR) |
| Absolute long indexed | `LDA $123456,X` | + X |
| Block move | `MVN src,dst` | bank-to-bank copy |

## Porting checklist for 65816 source

1. Establish E, M, X state at every point — they are a hidden part of the
   instruction's meaning. A routine often does `REP #$30` on entry and assumes
   16-bit throughout; a callee might change them and forget to restore.
2. Note the bank registers (DBR/PBR) and the direct page (D) — addresses in the
   source are relative to these, not absolute.
3. Data addresses are **24-bit and carry across bank boundaries**. A 16-bit
   access at `$12FFFF` reads its high byte from `$130000`, and indexing past
   `$xxFFFF` lands in the next bank. Only the program counter, the `(a,X)`
   pointer fetch, and direct-page/stack addressing (always bank 0) stay inside
   a bank. See [Bank boundaries and wrapping](#bank-boundaries-and-wrapping).
4. When in doubt, a IIgs routine that touches the toolbox or GS/OS is almost
   always native-mode 16-bit on entry. An SNES routine is native mode too: the
   reset handler leaves emulation mode almost immediately.

## Bank boundaries and wrapping

The WDC datasheet (§3.5) says data "may span 64 KByte bank boundaries", and
§7.3 says "indexing from page ZZFFXX may result in ZZ+1,00YY" on the 65C816
(where the 65C02 would wrap to `00YY`). Per-mode behavior, from the datasheet
plus Anomie's hardware tests on the SNES 5A22:

| Mode | Address calculation | 16-bit data access |
|------|---------------------|--------------------|
| PC increment | wraps within the program bank; PBR never changes by itself (code may not span banks) | — |
| `a` | `DBR:a` | high byte carries into the next bank |
| `a,X` / `a,Y` | `DBR:a` + index **carries** into the next bank | carries |
| `al` / `al,X` | full 24-bit; `+X` carries | carries |
| `(a)` (JMP) | pointer read from bank 0 | — (target stays in PBR) |
| `(a,X)` (JMP/JSR) | `a+X` wraps within the **program bank**; pointer read from the program bank | — (target stays in PBR) |
| `d`, `d,X`, `d,Y` | always **bank 0**; `D+d+X` never carries into bank 1 | carries across pages, stays in bank 0 |
| `(d)`, `(d,X)`, `[d]` | pointer read from bank 0 | carries across pages and banks |
| `(d),Y`, `[d],Y`, `(d,S),Y` | `+Y` added to the full pointer **carries** across banks | carries across pages and banks |
| `d,S` | always bank 0; may leave page 1 even in emulation mode | carries |

Emulation mode keeps 6502 page behavior in two places (datasheet §7.1–7.2):

- **Direct page with `DL = 0`:** `d`, `d,X`, `d,Y` and `(d,X)` pointer fetches
  wrap inside the direct page, the way 6502 zero-page addressing does.
  `[d]`, `[d],Y` and `PEI` are the exception and run into the next page. If
  `DL ≠ 0`, nothing wraps at the page.
- **Stack:** the stack is `$0100-$01FF`, but `JSL`, `JSR (a,X)`, `PEA`, `PEI`,
  `PER`, `PHD`, `PLD` and `RTL` can push or pull bytes outside page 1.

The WDC datasheet §3.5.2 says the `(a,X)` pointer is in bank 0, but hardware
tests (and bsnes) read it from the program bank. Trust the program bank.

## SNES / Ricoh 5A22 notes

The SNES CPU (Ricoh 5A22, "S-CPU") is a 65C816 core with extra hardware on the
same die: 8 DMA/HDMA channels, an 8×8 multiply / 16÷8 divide unit, H/V timer
IRQs, the V-blank NMI, auto-joypad reading, and WRAM refresh. The **instruction
set, flags and modes are identical** to the WDC part, so everything above
applies. The extra hardware is reached through memory-mapped registers at
`$4200-$43FF`. For what each address means, see the 6502-memory-map skill
(`references/snes-memory.md`).

What changes on the SNES:

- **Decimal mode works.** `SED` + `ADC`/`SBC` do real BCD, as on the IIgs. The
  NES 2A03's disabled decimal mode does **not** carry over.
- **Boot and vectors.** RESET always enters emulation mode through
  `$00FFFC` with PBR = DBR = `$00`. The reset code normally does
  `SEI : CLC : XCE` right away, and from then on the native vectors apply.
  Every vector is a 16-bit pointer read from the cartridge ROM at the end of
  bank `$00`:

  | Vector | Native (E=0) | Emulation (E=1) | SNES source |
  |--------|--------------|-----------------|-------------|
  | COP | `$FFE4` | `$FFF4` | `COP` instruction |
  | BRK | `$FFE6` | shares `$FFFE` with IRQ | `BRK` instruction |
  | ABORT | `$FFE8` | `$FFF8` | unused: the 5A22 has no ABORT input |
  | NMI | `$FFEA` | `$FFFA` | V-blank NMI (`$4200` bit 7) or the /NMI pin |
  | RESET | — | `$FFFC` | power-on / reset |
  | IRQ | `$FFEE` | `$FFFE` | H/V timer IRQ (`$4200`), or cart/expansion /IRQ (e.g. SA-1) |

  The rules that follow from this:
  - **An interrupt sets PBR to `$00` and leaves DBR alone.** The handler runs
    with the interrupted code's data bank and must set its own (`PHK : PLB`,
    or `PEA`/`PLB`). `XCE` changes neither bank register. Only RESET zeroes
    DBR. In native mode the old PBR is pushed and `RTI` restores it; in
    emulation mode it isn't pushed (datasheet §7.11).
  - Because the target bank is forced to `$00`, every handler entry point
    has to be in `$00:8000-$FFFF`. FastROM/HiROM games put a stub there that
    does a `JML` into a fast bank.
  - In emulation mode, BRK and IRQ share `$FFFE`. The handler tells them apart
    by the B bit (bit 4) of the P value pushed on the stack.
  - On SA-1 carts, the SA-1 can substitute the native NMI/IRQ vectors (see
    the 6502-snes-sa1 skill).
- **Cycle counts are not elapsed time.** Opcode tables count CPU cycles, but
  each SNES CPU cycle lasts a different number of master clocks (~21.477 MHz
  NTSC):
  - an internal (IO) cycle takes 6;
  - a memory access takes 6 (Fast), 8 (Slow) or 12 (XSlow), depending on the
    address and the FastROM bit (`$420D` bit 0).

  To time code, walk it cycle by cycle. On top of that, DMA, HDMA, and a 40
  master-cycle WRAM refresh on every scanline pause the CPU.
- **No multiply/divide instructions.** Code uses the hardware unit instead:
  write `$4202`/`$4203` and read the product from `$4216/7` after 8 CPU cycles,
  or write `$4204-$4206` and read `$4214-$4217` after 16 cycles. Reading too
  early returns partial results. The NOPs or other filler after the write are
  deliberate.
- **Interrupt-flag latency.** `CLI`, `SEI`, `PLP`, `REP #$04` and `SEP #$04`
  change `I` in their final cycle, but the IRQ check for that instruction
  happens just before it. So an IRQ can still be taken right *after* a `SEI`,
  and a `CLI` doesn't let an IRQ in until one instruction later. `RTI`, `BRK`
  and `COP` don't have this delay. If NMI and IRQ are both pending, NMI wins.
  Leaving `WAI` takes 12 master cycles.
- **Open bus.** Reading an unmapped address doesn't fault. It returns the last
  value on the data bus, usually the last operand byte of the same
  instruction. Internal (IO) cycles don't change that value. Some shipped code
  works only by accident of open bus, such as reads of the write-only `$4200`.
- **A second 65C816 on some carts.** SA-1 cartridges add another 65C816 core at
  10.74 MHz with its own memory map. See the 6502-snes-sa1 skill.
